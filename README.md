# Sonar для OpenCode

Навык `/sonar` помогает разбирать замечания SonarQube прямо в OpenCode: находит соответствующий код, объясняет проблему по-русски, предлагает варианты и вносит **только согласованные** исправления.

Навык ориентирован прежде всего на проекты **1С (BSL)**, но сам процесс получения и учёта замечаний не привязан к одному языку.

## Что умеет

- Разбирает замечания по модулям, с указанием функции и строки.
- Отличает потенциальные ошибки от замечаний по оформлению; не принимает вывод Sonar за доказательство дефекта без проверки кода.
- Предлагает выбор: исправить, пропустить или отложить. Независимые решения остаются за вами.
- Запоминает ответы, умеет продолжать незаконченный разбор и пересматривать пропущенное.
- Применяет согласованные изменения пакетно после обсуждения замечаний модуля.
- Не делает коммиты, не меняет Git-ветку и не обращается к SonarQube от вашего имени.

## Что потребуется

- **OpenCode** с поддержкой slash-команд навыков.
- **Python 3.9 или новее** в `PATH` (команда `python`). Сторонние Python-пакеты не нужны. Локальные проверки этой версии выполнены на Python 3.13; отдельной проверки всех поддерживаемых версий Python нет.
- Доступ к странице замечаний **SonarQube в браузере**, где вы уже авторизованы.

Для более точного разбора BSL полезны, но **не обязательны**, навыки `bsl-sonar-rules`, `bsl-code-review` и MCP `rlm-tools-bsl`. Если их нет, `/sonar` предупредит и продолжит с доступным кодом.

> По сведениям исходной рабочей версии автоматическое получение JSON использовалось с локальной SQLite-историей OpenCode Desktop 1.19.2. Это не гарантия совместимости с другими версиями: при удалённой истории, другой схеме БД или отсутствии записи выполняемой команды приём остановится с объяснением. В рамках подготовки публичной версии выполнены Python-тесты, а не полный интерактивный прогон в OpenCode.

## Установка на Windows

1. Склонируйте репозиторий (или скачайте исходники ZIP с GitHub и откройте распакованную папку):

   ```powershell
   git clone https://github.com/mishakov1c/opencode_sonar_skill.git
   cd opencode_sonar_skill
   ```

   Если у вас переносимый архив навыка, распакуйте его и откройте папку `sonar`.

2. В PowerShell скопируйте навык в глобальный каталог OpenCode:

   ```powershell
   $target = "$HOME\.config\opencode\skills\sonar"
   New-Item -ItemType Directory -Force -Path "$target\scripts" | Out-Null
   Copy-Item .\SKILL.md -Destination $target -Force
   Copy-Item .\README.md -Destination $target -Force
   Copy-Item .\scripts\sonar_index.py, .\scripts\sonar_ingest.py, .\scripts\sonar_state.py -Destination "$target\scripts" -Force
   ```

   Итоговый файл должен находиться по адресу `%USERPROFILE%\.config\opencode\skills\sonar\SKILL.md`.

3. **Полностью перезапустите OpenCode**. Теперь можно вызывать `/sonar`.

> Репозиторий с исходниками и установленный навык — разные папки. После `git pull` изменения **не попадут автоматически** в OpenCode: повторите копирование и перезапуск.

## Быстрый старт

1. Откройте в OpenCode проект, замечания которого нужно разобрать, и введите:

   ```text
   /sonar
   ```

2. Пришлите ссылку на страницу замечаний SonarQube, например:

   ```text
    https://sonar.example/project/issues?id=example_project&pullRequest=123&resolved=false
   ```

3. Агент выдаст **API-ссылку и остановится**. Откройте её в своём браузере, скопируйте **весь JSON-ответ** и вставьте его следующим сообщением **текстом**, не файлом. Если замечаний больше одной страницы, агент попросит следующие страницы.

4. После получения JSON агент сверит проект и Git-контекст, прочитает затронутый код и начнёт задавать вопросы по замечаниям. Вы выбираете действия, после чего агент внесёт только согласованные изменения.

**Важно:** OpenCode самостоятельно не запрашивает SonarQube. Не отправляйте агенту логин, пароль, токены или cookie.

Проект и номер PR в примере вымышленные. Для своего проекта используйте его настоящую ссылку, не меняя вручную ключи в JSON.

## Основные команды

| Команда | Назначение |
| --- | --- |
| `/sonar` | Новый разбор; прошлые результаты сохраняются. |
| `/sonar resume` | Продолжить незаконченный разбор. |
| `/sonar skipped` | Вернуться к ранее пропущенным замечаниям. |
| `/sonar detailed` | Подробный режим: по одному вопросу за раз. |

По умолчанию включён быстрый режим: связанные замечания объединяются, а несколько **независимых** вопросов могут показываться одной партией. В любом режиме решение принимает пользователь.

Если повторно загрузить замечания того же PR, навык сопоставит их с прежними и предложит, какие решения оставить, а какие пересмотреть. Исчезновение замечания в SonarQube подтверждается **только новым анализом Sonar**, а не локальной правкой.

## Где хранятся результаты

Выгрузки Sonar, индекс, состояние разбора и история решений сохраняются вне проекта:

```text
%USERPROFILE%\.config\opencode\sonar-reports\
```

Не добавляйте эту папку в Git и не публикуйте её содержимое: там могут быть внутренние данные проекта. При обновлении или удалении навыка результаты автоматически не удаляются.

SQLite-история читается **только для чтения** из `$XDG_DATA_HOME/opencode/opencode.db`, а если переменная не задана — из `~/.local/share/opencode/opencode.db`. Текущая сессия определяется по уникальной метке запущенного вызова `sonar_ingest.py`, а не по времени последней активности. Нужны таблицы `session`, `message`, `part`, JSON-функции SQLite и сохранённый статус вызова `running`. История другого формата не поддерживается; механизм не выбирает другую сессию при ошибке.

Пути вычисляются относительно домашнего каталога текущего пользователя; скрипты запускаются из каталога установленного навыка или по абсолютному пути. Удалённая история не поддерживается. Настройки Git, имя пользователя, целевая ветка, другие навыки и MCP не задаются этим репозиторием. Правила оформления изменений берутся из инструкций вашего проекта.

Если OpenCode не поддерживает slash-команды навыков или подстановку аргументов в `$ARGUMENTS`, перечисленные команды могут быть недоступны. Если инструмент интерактивных вопросов отсутствует, навык задаёт те же вопросы текстом и ждёт ответа.

## Если что-то не работает

- **Команда `/sonar` не появилась.** Проверьте путь к `SKILL.md`, версию OpenCode и перезапустите приложение.
- **Вместо JSON открылась страница входа.** Откройте API-ссылку в браузере с активной авторизацией SonarQube.
- **JSON не принят.** Вставляйте полный ответ текстом, без сокращений и посторонних сообщений.
- **Не удалось прочитать историю OpenCode.** Автоматический приём зависит от поддерживаемого локального формата истории; навык остановится и сообщит причину, а не возьмёт данные из случайной сессии.
- **Неясна целевая ветка PR.** Агент должен уточнить её, а не предполагать `develop`.

## Разработка и тестирование

В репозитории есть тесты и диагностический скрипт для анализа расхода токенов. Для обычного использования они не нужны.

```powershell
python scripts/test_sonar.py
python scripts/test_sonar_ingest.py
python scripts/test_sonar_measure.py
python scripts/test_build_zip.py
```

Сборка переносимого архива:

```powershell
python scripts/build_zip.py --output sonar-opencode-skill.zip
```

Архив содержит ровно пять файлов под каталогом `sonar/`: `SKILL.md`, `README.md` и три рабочих скрипта `sonar_index.py`, `sonar_ingest.py`, `sonar_state.py`. Тесты, сборщик, диагностический `sonar_measure.py`, пользовательские JSON и Git-история в него не попадают. Диагностический скрипт в исходниках запускается только вручную; реальные экспорты для тестов не нужны.

Внутренняя логика работы агента находится в [`SKILL.md`](SKILL.md). Изменять её при установке не требуется.

---

Навык не запускает BSL Language Server, Sonar Scanner или Java и не отправляет изменения в Git без разрешения.

Рефакторинг старого BSL-кода ради Cognitive/Cyclomatic Complexity предлагается отдельно и выполняется только с согласия пользователя. Исчезновение замечания подтверждается повторной выгрузкой, а не локальным исправлением.
